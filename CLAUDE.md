# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

TB-DOTS CAR CDSS is a research project building ML-based Clinical Decision Support System for Pulmonary Tuberculosis (PTB) treatment outcome prediction using data from the Cordillera Administrative Region (CAR), Philippines, 2015–2025. The project produces both trained models and a LaTeX/APA academic paper.

## Running the Pipelines

### Static model experiments (classical ML)

Must be run from the `static-model/` directory because `run_experiments.py` uses a local import of `experiment_pipeline`:

```bash
cd static-model
python run_experiments.py
```

This trains 6 classifiers × 4 sampling strategies, exports LaTeX tables to `paper/apa/tables/`, and saves the best model as `models/tb_outcome_prediction.onnx`.

To test the pipeline class in isolation:

```bash
cd static-model
python experiment_pipeline.py
```

### Temporal preprocessing pipeline

Run from the project root:

```bash
python preprocessing.py
```

Reads `dataset/temporal/combined_dataset.csv`, outputs model-ready arrays and CSVs to `dataset/temporal/output/`.

### Data consolidation (one-time setup)

```bash
cd static-model/scripts
python consolidate_non_temporal_data.py
```

Merges yearly raw CSVs from `dataset/non-temporal/yearly_raw/` into the consolidated and ML-ready CSVs.

### Install dependencies

```bash
pip install -r requirements.txt
# Additional packages needed at runtime (not in requirements.txt):
pip install xgboost lightgbm imbalanced-learn skl2onnx scipy
```

## Architecture

### Two parallel modeling tracks

**Static model track** (`static-model/`): Each patient is a single row. Binary classification predicting treatment success (Cured or Treatment Completed = 1) vs failure (Died, LTFU, Failed = 0).

- `experiment_pipeline.py` — `TBExperimentPipeline` class encapsulating data loading, feature selection, preprocessing, model definitions, experiment execution, and LaTeX export. The `_pipeline` column in results DataFrames holds the fitted sklearn pipeline object and must be dropped before LaTeX export.
- `run_experiments.py` — Orchestrates two experiment versions (baseline features vs improved features) × 4 samplers (None, SMOTE, SMOTE-ENN, SMOTE-Tomek). Selects best model by ROC-AUC and exports to ONNX via `skl2onnx`. ONNX export strips the `imblearn` sampler step since `skl2onnx` only supports `sklearn` pipelines.
- Dataset: `dataset/non-temporal/2015-2025-ml-ready.csv` (label-encoded, scaled) and `2015-2025-consolidated-clean.csv` (human-readable).

**Temporal track** (`preprocessing.py` + `dataset/temporal/`): Each patient has 13 monthly observations (M0–M12). The pipeline produces 3D tensors `(n_patients, 13, n_features)` intended for RNN/LSTM models.

- 13-stage pipeline: schema validation → identifier removal → type coercion → categorical harmonization → drop uninformative columns → wide→long reshape → MICE imputation (with forward-fill for temporal columns to prevent leakage) → one-hot encoding → StandardScaler → IQR+Z-score outlier capping → 3D tensor construction → validation → export.
- Outputs to `dataset/temporal/output/`: `X_temporal.npy` (3D, for LSTM), `X_static.npy` (2D, for tabular), `X_combined_flat.npy` (2D, flattened temporal+static for XGBoost), `static_features.csv`, `temporal_features.csv`, `cleaned_combined_dataset.csv` (pre-encoding, human-readable).
- Note: `preprocessing.py` exists at both the project root and `dataset/temporal/` — they are identical. The root version is the canonical one.

### Paper output

LaTeX tables are auto-generated by `TBExperimentPipeline.export_to_latex()` and written to `paper/apa/tables/`. The thesis source is at `paper/apa/thesis_apa.tex`.

### Target variable encoding

The static model dataset uses numeric-encoded outcome labels mapped alphabetically. `TBExperimentPipeline.load_data()` decodes them using `OUTCOME_DECODE` and then binarizes: success outcomes `{TREATMENT COMPLETED, CURED}` → 1, failure outcomes `{DIED, LOST TO FF-UP, FAILED}` → 0. All other outcome categories are excluded from modeling.

### Train/test split

Static model experiments use a 70/20/10 split: 10% validation held out first, then the remaining 90% is split 70/20 (train/test) via two sequential `train_test_split` calls with `stratify=y`.

### Class imbalance

The dataset is imbalanced (more successes than failures). Models use `class_weight='balanced'` or `scale_pos_weight` (for XGBoost). The resampling experiments additionally apply SMOTE variants at the pipeline level via `imblearn`.
